# 选择器样式统一

问题：快速添加使用原生优先级菜单，任务详情使用独立的 P1–P4 按钮；项目、分组、排序及日志筛选也分别定义样式，与已有日期弹层不一致。目标是在不改动数据格式、筛选语义和任务操作的前提下，统一选择器的视觉与交互。

方案比较：仅修改原生 select 的外框无法控制跨平台菜单样式；引入大型组件库会增加离线资源与主题覆盖成本；采用轻量共享 Select 组件，可复用现有 React、Lucide 和日期弹层样式，统一按钮和菜单，选用此方案。保留现有字体与暖白、细边框、红色强调，优先级以旗帜和文字共同区分，P4 明确为无优先级。

实现：通用 Select 负责触发器、浮层定位、当前值和选中标记、长选项滚动、键盘方向键/Home/End/Enter/Escape/Tab及外部点击关闭。菜单通过 portal 渲染，避免被表单和看板的滚动容器裁切；在视口边缘自动调整位置。PrioritySelect 在快速添加和详情页复用同一组选项。迁移项目、版块、重复规则、分组、排序、日志筛选和卡片移动控件；日期选择器保留日历逻辑，共用视觉变量。标签多选继续保持适合多选的按钮形式。

验证：组件测试检查键盘选择、取消、焦点恢复、禁用选项、点击选项不提交外层表单和重复选择动作。更新现有看板移动集成测试，并验证快速添加及详情保存优先级的行为。运行完整测试与生产构建，浏览器检查桌面和390宽弹层、长选项、日志筛选、版块移动及日期弹层，不改动用户原有任务数据。
